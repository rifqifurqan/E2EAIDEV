- Parser interface + ingest service for uploaded text/markdown; safe Docling boundary (FR-D1, FR-D3, FR-D4):
  - New `ingest.py`: a `Parser` protocol + `ParsedChunk`; `TextMarkdownParser` (structure-aware: splits on
    ATX headings, carries the heading trail as `section_path`, counts form-feed page breaks); `DoclingParser`
    adapter that raises a clear AppError(503) when Docling is not installed (it isn't here), so rich formats
    (PDF/DOCX/PPTX/XLSX/images) are routed but recorded as a failed parse until the worker image lands.
    `select_parser(mime)` routes text/* to the markdown parser and everything else to Docling.
  - `ingest_version(session, embedder, version_id, storage)`: reads the stored object by object_key, parses it,
    (re)writes chunks idempotently per version_id (PRD F1.6), sets parse_status ready/failed with an audit row,
    then indexes embeddings through the existing `index_document_chunks`/LiteLLMEmbedder path. On a parser error
    it marks the version failed and writes no chunks (nothing to leak). No heavy Docker worker added (5 GB VM):
    it runs inline and is callable as a service, the `POST /api/v1/documents` route, and the new operator
    command `e2eai-api ingest-version <version_id>`.
  - `documents.py`: `create_uploaded_document` now stores the object + a `pending` version only (chunking moved
    to ingest, PRD F1.2); added `LocalObjectStorage.get_bytes`; the upload route stores then ingests and returns
